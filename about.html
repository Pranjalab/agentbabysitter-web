About Agent Babysitter

What it is, why it exists, and how to reach the person who builds it.

What it is

Agent Babysitter — abs on the command line — is an open-source remote control for Claude Code, driven from Telegram. It monitors a Claude Code session running on your own machine, messages your phone when a task finishes, and takes your reply straight back into that same live session rather than starting a new one. You can send screenshots it reads directly, speak to it and be spoken back to, check your Claude usage limits, and start or resume a session — all from the chat.

There is no server in the middle. Telegram is polled outbound from your machine, so nothing needs a public IP, an open port or a webhook, and no copy of your code or your conversation goes anywhere except between your machine and your own private bot.

Why it exists

Claude Code will happily work for twenty minutes on its own. The problem is the twenty minutes: you either sit and watch a terminal, or you walk away and lose the thread. Every existing answer wanted a second copy of the session somewhere else, or a server, or gave you a chat window that could not actually steer the thing already running.

So this went the other way round. The session stays exactly where it is, on your machine, with your files and your permissions. Telegram is only a window into it — which is why a reply lands in the same session, and why a message from a phone is treated as lower-trust than your hands on the keyboard.

Who builds it

One person: Pranjal, who wanted to leave his desk while Claude was working and ended up writing the thing that made it possible. It is built in the open, released under the MIT licence, and every feature on the docs page links to the line of source that implements it — partly as documentation, partly so nothing about a tool with this much access has to be taken on trust.

It is a side project, honestly described. Issues get read, pull requests get reviewed, and the release notes say what broke as well as what landed.

How to reach us

Anything about the tool is best in the open, where the next person with the same question can find the answer. Everything else has a route below.

Something is broken

Open a bug report. The template asks for your OS, your shell and the output of abs doctor, which is usually enough to find it without a round trip.

GitHub Issues

You want it to do something

Open a feature request and say what you were trying to do. Half the features here started as somebody describing the moment it annoyed them.

GitHub Issues

You want to send a patch

Pull requests are welcome — one logical change each, and read CONTRIBUTING first: it is short, and it says how to run the test suite. For anything large, open an issue and ask before you build it twice.

Pull requests

You found a security problem

Please do not open a public issue. The security policy has the threat model and how to report something sensitively; the security page sets out what this does and does not protect against.

Security policy

Anything else

Email works. Feedback, a question that does not fit an issue, or just hello — it reaches one person, and it gets read: pranjal.panda.ai@gmail.com

Email

You just want to follow along

Star or watch the repository and you will see each release as it lands. The releases page keeps the plain-English version of what changed.

GitHub

Start using it

One line, on macOS or Linux, with Claude Code already installed and logged in. The command and the first-run walkthrough are on the home page; the docs cover everything after that. If you want the whole picture first, how the Telegram integration works walks through it end to end.
